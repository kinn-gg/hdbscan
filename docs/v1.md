# Version 1 compatibility and support

The v1 public API is the exported surface locked by `TestPublicAPISnapshot`.
Within v1, exported identifiers and method signatures remain source compatible;
new identifiers may be added in minor releases. Behavioral bug fixes may change
tie-sensitive labels while preserving the documented deterministic order and
partition guarantees. Experimental accelerators, float32 storage, GPU/offload,
mmap data, and parallel dendrogram construction are not part of the portable v1
API and are not required for correctness.

Supported inputs are finite row-major float64 vectors, dense precomputed distance
matrices, and symmetric CSR distance graphs. The portable implementation builds
and runs on linux, darwin, and windows for amd64 and arm64. Architecture kernels
are optional; pure Go fallbacks define correctness. Numerical behavior, including
overflow-safe Euclidean distance and cross-architecture reassociation tolerance,
is specified in [numerics](numerics.md).

The security and robustness review covers shape-overflow validation, non-finite
values, invalid custom metric output, malformed CSR indices, disconnected graphs,
bounded worker counts, cancellation, caller buffer lengths, nil writers, and
opt-in memory-heavy state. Go fuzz targets cover metrics, vector kernels, the
reference hierarchy, partition canonicalization, and FLASC. Release candidates
run the race detector and extended fuzzing; no parser accepts untrusted executable
content and the package performs no network or filesystem I/O except explicit
streaming writes supplied by the caller.

Benchmark methodology is published in [benchmarking](benchmarking.md). Results
must state Go version, OS/architecture, CPU, workers, dataset recipe, ns/op,
allocations, and peak RSS when making memory claims. amd64 measurements and arm64
compile/race validation are release gates; an unavailable physical arm64 benchmark
must be reported as missing, never inferred from cross-compilation.

# HDBSCAN for Go: implementation milestones

This roadmap ports the public behavior and algorithms of
[`scikit-learn-contrib/hdbscan`](https://github.com/scikit-learn-contrib/hdbscan)
to an idiomatic, fast, memory-conscious Go library. It is ordered by dependency:
each milestone must meet its exit criteria before an optimization or higher-level
feature is built on it.

## Project goals

- Match the upstream HDBSCAN\* results for supported inputs, including labels,
  membership probabilities, cluster persistence, condensed trees, and outlier
  scores. Cluster IDs may differ, so parity tests compare partitions rather than
  raw label numbers.
- Make the normal dense-vector path subquadratic in memory. Never materialize an
  `n x n` distance matrix unless the caller explicitly supplies one or selects the
  reference implementation.
- Provide deterministic results for a fixed input and configuration, independent
  of worker scheduling. Define stable tie-breaking once and test it everywhere.
- Keep the portable implementation in pure Go. Put architecture-specific SIMD
  kernels behind build tags and runtime CPU checks, with identical scalar
  fallbacks.
- Measure before optimizing. Every performance change needs benchmarks,
  allocation measurements, and parity tests.
- Preserve the upstream BSD-3-Clause notices for code that is translated rather
  than independently implemented.

## Supported scope

The first stable release targets in-memory `float64` row-major observations,
precomputed dense distances, Euclidean/Manhattan/Minkowski metrics, HDBSCAN\*, EOM
and leaf selection, probabilities, persistence, and GLOSH scores. Later milestones
add prediction, additional metrics, robust single linkage, sparse/precomputed
graphs, and branch detection.

Python plotting and integrations with pandas, NetworkX, joblib, and scikit-learn
are not ported. Instead, tree and graph data are exposed as Go values suitable for
JSON/CSV export and downstream visualization.

## Target package shape

```text
hdbscan                 Public estimator, options, results, prediction
internal/distance       Scalar and SIMD distance kernels
internal/knn            Brute-force, k-d-tree, and later ball-tree search
internal/mst            Prim and Boruvka mutual-reachability MSTs
internal/hierarchy      Linkage, condensation, stability, cluster selection
internal/disjointset    Allocation-free union-find
testdata/parity         Versioned fixtures generated by upstream Python
```

The public API should favor an immutable configuration and explicit results:

```go
model, err := hdbscan.New(hdbscan.Config{
    MinClusterSize: 10,
    MinSamples:     10,
    Metric:         hdbscan.Euclidean,
    Workers:        runtime.GOMAXPROCS(0),
})
result, err := model.Fit(ctx, hdbscan.Dense64{Data: x, Rows: n, Cols: d})
```

`Fit` must honor cancellation. Results own their exported slices unless an API is
explicitly documented as a view.

## M0 — Specification, fixtures, and benchmark harness

**Outcome:** a reproducible definition of compatibility and performance before
implementation choices become entrenched.

### Work

- Pin an upstream `hdbscan` release/commit and record its BSD-3-Clause license.
- Document parameter semantics and defaults: `min_cluster_size`, `min_samples`,
  `alpha`, EOM/leaf selection, epsilon/persistence thresholds, maximum cluster
  size, single-cluster behavior, and non-finite input handling.
- Write a small Python fixture generator that emits inputs and canonical upstream
  outputs as JSON or a compact binary format.
- Cover tiny and adversarial cases: empty/one-point inputs, duplicate points,
  equal-distance ties, all noise, one cluster, disconnected precomputed graphs,
  non-finite values, high dimensional data, and fixed synthetic datasets.
- Establish Go unit, fuzz, race, and benchmark suites. Record wall time, bytes/op,
  allocations/op, peak RSS, dataset shape, CPU model, Go version, and worker count.
- Define partition comparison (adjusted Rand index or pairwise co-membership),
  numeric tolerances, deterministic edge ordering, and NaN/Inf policy.

### Exit criteria

- Fixture generation is repeatable from a locked Python environment.
- CI runs correctness tests on Linux, macOS, and Windows and benchmarks on one
  pinned Linux runner without using benchmark results as flaky pass/fail tests.
- A benchmark corpus includes low-dimensional spatial data, high-dimensional data,
  duplicates/ties, and noise-heavy data at small, medium, and large sizes.

## M1 — Data model, metrics, and portable vector kernels

**Outcome:** allocation-free distance primitives and validated input types shared
by every algorithm.

### Work

- Implement a contiguous row-major `Dense64` input with overflow-safe shape and
  finite-value validation. Avoid `[][]float64` in hot paths.
- Define a metric interface that supports optimized built-ins and a custom metric
  fallback. Implement squared Euclidean, Euclidean, Manhattan, Minkowski, and
  precomputed distance access.
- Use squared distances internally wherever ordering is unchanged; take square
  roots only where HDBSCAN semantics require actual distances.
- Implement scalar kernels with zero heap allocations. Hoist bounds checks, use
  cache-friendly blocking, and reuse caller- or pool-owned work buffers.
- Add optional `amd64` and `arm64` vector kernels for dot products/distance blocks.
  Dispatch once per fit, never inside the inner loop. Require bitwise or documented
  tolerance parity with the scalar path.
- Benchmark dimensional break-even points. SIMD remains optional when call or tail
  overhead makes short vectors slower.

### Exit criteria

- Metric tests match high-precision reference values, including zero-length,
  duplicate, very large, and very small vectors.
- Built-in metric calls allocate `0 B/op` in steady state.
- Scalar and SIMD kernels pass the same fuzz corpus and do not change clustering
  under the documented tolerance/tie policy.
- Benchmarks publish throughput by vector dimension and architecture.

## M2 — Correct reference pipeline

**Outcome:** a simple end-to-end HDBSCAN\* implementation used as a correctness
oracle, intentionally limited to smaller datasets.

### Work

- Compute core distances from a full or streamed pairwise-distance calculation.
- Implement mutual reachability distance:
  `max(core[a], core[b], distance(a,b)/alpha)`.
- Build an exact minimum spanning tree with dense Prim, using deterministic ties.
- Implement union-find, MST-to-single-linkage conversion, hierarchy condensation,
  cluster stability, EOM and leaf selection, labels, probabilities, persistence,
  and GLOSH outlier scores.
- Expose the MST, single-linkage tree, and condensed tree as typed Go records.
- Clearly name this route `Reference` and document its `O(n^2)` time and memory (or
  `O(n)` auxiliary memory when distances are streamed) characteristics.

### Exit criteria

- All M0 fixtures pass for both EOM and leaf selection.
- Partitions match upstream exactly after canonical label remapping for unambiguous
  cases; tie-sensitive cases match the recorded deterministic policy.
- Tree invariants are property-tested: `n-1` MST edges, acyclic connectivity,
  monotonic linkage, valid parent/child sizes, and probability range `[0,1]`.
- The race detector, fuzz tests, and cancellation tests pass.

## M3 — Memory-efficient exact Euclidean engine

**Outcome:** the default low-/moderate-dimensional path no longer constructs all
pairwise distances.

### Work

- Implement an exact k-d tree over index arrays and the original contiguous data;
  do not copy point vectors into tree nodes.
- Compute `min_samples` core distances with bounded per-worker heaps or selection
  buffers sized `O(min_samples)`, reused across queries.
- Implement exact dual-tree or tree-pruned Boruvka for the mutual-reachability MST.
  Start from the upstream algorithm, but isolate tree traversal from metric and
  union-find state so the implementation is testable.
- Store edges in a packed struct-of-arrays or compact struct after measuring both.
  Preallocate at most `n-1` final MST edges and reuse component scratch space.
- Parallelize independent tree traversals with coarse tasks and bounded workers.
  Merge candidate edges in stable component order to preserve determinism.
- Fall back to the reference/blocked brute-force route when dimension or data
  distribution makes the tree ineffective.

### Exit criteria

- The exact engine produces the same canonical MST/hierarchy as M2 on fixtures,
  including duplicates and distance ties.
- Auxiliary memory is `O(n * d + n * min_samples + n * workers)` or better and is
  demonstrated with peak-RSS benchmarks; no hidden `O(n^2)` allocation exists.
- On the agreed low-dimensional benchmark corpus, the engine is faster than M2 and
  scales to a dataset at least 10x larger within the same memory budget.
- Parallel execution is race-free, cancellable, and deterministic at worker counts
  `1`, `2`, and `GOMAXPROCS`.

## M4 — Optimized algorithm selection and approximate mode

**Outcome:** good performance across dimensionalities without forcing callers to
understand the internal algorithm portfolio.

### Work

- Add blocked, parallel brute-force k-NN/core-distance calculation for high
  dimensions, vectorizing distance batches and bounding scratch memory.
- Add a ball tree only if benchmark data shows a material win for metrics/data not
  served by the k-d tree. Do not add it for API symmetry alone.
- Add an opt-in approximate neighbor/MST path behind an interface so an ANN backend
  can be replaced without changing public results. Always label results as
  approximate in metadata.
- Implement a deterministic `Auto` selector using dataset size, dimension, metric,
  and sampled tree-pruning effectiveness. Make forced algorithm selection public
  for repeatable benchmarks.
- Add oversubscription controls: one bounded worker pool for the full fit, no
  nested unbounded goroutines, padded per-worker counters where false sharing is
  measurable.

### Exit criteria

- `Auto` is never catastrophically worse than the best exact built-in path on the
  benchmark matrix (set and publish a threshold, initially 1.5x).
- Approximate mode reports clustering quality (ARI), MST edge recall, speedup, and
  peak memory against exact mode; documented defaults prioritize quality.
- Large-data benchmarks show bounded memory and useful multicore scaling without
  goroutine growth proportional to pair count.

## M5 — Public v0.1 API and production hardening

**Outcome:** a dependable core Go library suitable for real applications.

### Work

- Finalize options, validation errors, context cancellation, result ownership, and
  algorithm metadata. Keep the API small enough to evolve before v1.
- Add `Fit`, `FitPredict`, and extraction of flat clusters from retained hierarchy
  at alternate epsilon/selection settings without recomputing neighbors or MST.
- Provide streaming encoders for tree/MST export so callers need not build another
  full in-memory representation.
- Add examples, algorithm/complexity docs, numerical reproducibility notes, memory
  sizing guidance, profiling instructions, and licensing/attribution.
- Add CI for `go test`, `-race`, fuzz smoke tests, static analysis, coverage,
  cross-compilation, API compatibility checks, and reproducible releases.

### Exit criteria

- Core feature parity is documented in a Python-to-Go compatibility matrix.
- No known correctness failure exists in the parity corpus; public packages have
  examples and complete Go documentation.
- Performance targets are set from M0 baselines and met on a pinned host. Recommended
  initial gates: no more than `1.25x` upstream runtime and `0.75x` upstream peak RSS
  on the primary low-dimensional exact benchmark, with results published rather
  than silently relaxed.
- v0.1.0 is tagged with BSD-3-Clause attribution and benchmark results.

## M6 — Prediction and soft membership

**Outcome:** assign new observations and request soft memberships without refitting.

### Work

- Retain compact prediction data during fit only when requested, avoiding default
  memory overhead.
- Port approximate prediction, prediction scores, a single-point membership vector,
  and all-points membership vectors.
- Batch queries to reuse tree searches and vector kernels. Provide iterator or
  caller-buffer APIs for all-cluster membership output, which can itself be large.
- Specify behavior for novel points, noise, single-cluster models, non-finite input,
  and models fitted from precomputed distances.

### Exit criteria

- Prediction labels, strengths, and membership vectors match upstream fixtures
  within documented tolerances.
- Batched prediction has bounded scratch memory and no per-point heap allocation in
  the built-in dense metric path.

## M7 — Extended parity: metrics, sparse inputs, and robust single linkage

**Outcome:** broaden compatibility without slowing the core dense Euclidean path.

### Work

- Prioritize additional metrics from observed demand and upstream coverage. Each
  optimized metric declares which spatial indexes are mathematically valid.
- Support caller-provided precomputed sparse distance graphs with explicit
  disconnected-component semantics. Do not silently densify.
- Implement robust single linkage and hierarchy cuts using the shared neighbor,
  MST, linkage, and tree representations.
- Add the density-based cluster validity index, with streaming/chunked work where
  a naive formulation would allocate quadratically.

### Exit criteria

- The compatibility matrix and parity fixtures cover every added metric/input mode.
- Sparse inputs remain sparse through the pipeline, verified by allocation and RSS
  tests.
- Robust single linkage and validity scores match upstream fixtures.

## M8 — Branch detection (FLASC), v1 API, and long-term optimization

**Outcome:** complete the meaningful algorithmic surface of current upstream and
stabilize the Go API.

### Work

- Port branch-detection data, cluster approximation graphs, branch hierarchies,
  branch persistence/membership, and approximate branch prediction.
- Design graph storage around packed indices and weights; offer streaming export
  and avoid duplicate adjacency representations where possible.
- Profile end to end before adding further SIMD/assembly. Consider float32 storage,
  GPU/offload, mmap/external-memory data, or parallel dendrogram construction only
  as separate experimental packages with quantified accuracy/complexity tradeoffs.
- Run a v1 API review, security/robustness audit, long-duration fuzzing, and
  benchmarks on amd64 and arm64.

### Exit criteria

- Branch results match pinned upstream fixtures and the published FLASC examples.
- No experimental accelerator is required for correctness or for the portable API.
- v1 compatibility guarantees, numerical guarantees, supported architectures, and
  benchmark methodology are published.

## Cross-cutting engineering rules

### Correctness

- Compare cluster partitions, not incidental numeric cluster IDs.
- Sort equal-weight edges by a documented `(weight, min(u,v), max(u,v))` order.
- Keep an independently simple reference path; optimized code must never become its
  own only oracle.
- Differential-test scalar/SIMD, serial/parallel, reference/exact-tree, and Go/Python
  implementations on randomized datasets.

### Memory

- Use integer point indices and contiguous primitive slices in hot data structures.
- Preallocate from known upper bounds, reuse scratch buffers, and clear pooled
  references before reuse. Pool only objects large enough to justify retention.
- Avoid interfaces, closures, maps, and per-edge pointers in inner loops.
- Track both Go heap allocations and process peak RSS; SIMD buffers, stacks, and
  foreign/OS memory can make heap-only numbers misleading.
- Treat all-pairs distances, all-membership matrices, exported graphs, and retained
  prediction data as explicit opt-in memory costs.

### Performance

- Vectorize arithmetic-heavy, contiguous loops: distance blocks, reductions, and
  selected membership calculations. Tree traversal and union-find are usually
  latency/branch bound and should first be optimized for layout and locality.
- Use architecture-specific assembly only after portable blocked kernels are
  benchmarked. Keep a pure-Go build and test it continuously.
- Partition parallel work into coarse deterministic chunks. Bound concurrency by
  configuration and available work; never launch one goroutine per point or edge.
- Preserve benchmark history with `benchstat`-compatible output and profiles for
  claimed improvements.

| `v1.0` | M8 | Branch detection and stable public API |

## First implementation slice

Begin with M0 and M1 in parallel only after the configuration and fixture formats
are agreed. Then implement M2 as a vertical slice: Euclidean input → core distances
→ mutual-reachability MST → condensed tree → EOM labels/probabilities. This yields
a trustworthy oracle and usable result before introducing the substantially more
complex tree-pruned Boruvka engine in M3.
